# Generated cached_float80.rs adoption

The full Rust input and raw output are in `raw/`. Production
`src/commonMain/kotlin/io/github/kotlinmania/serdejson/lexical/generated/cachedfloat80/CachedFloat80.kt`
adds only a Kotlin package declaration to those exact generated bytes. All source
items and comments are retained; none are configured out. Generator commit
**959f4e9** resolves the source records through existing Syn nodes, without a
file-specific translation template. Supporting record declarations are data
contracts, not whole cached.rs method/trait translations.

The former handwritten constants in `lexical/CachedFloat80.kt` are replaced with
an explicit integration adapter. It converts generated read-only lists to the
existing Cached.kt primitive arrays once, preserving the cached.rs methods and
existing callers. No constants or algorithms are copied into the adapter. The
adapter is hand-written integration code, never counted as machine output.
`CachedFloat80.before.kt` and `adapter.diff` preserve that boundary and old baseline.

All 124 macOS ARM64 Native tests pass, including all 169 Rust table value/length
observations through the production ExtendedFloatCache API and checks of the
existing getSmall/getLarge/getSmallInt methods. Raw Kotlin was also independently
compiled unchanged and compared with Rust before adoption. Pointer identity and
unsafe mutation are outside that source-mapping contract. Other platforms are
unverified; no dependency, configuration, target or FFI changes were made.

The pre-existing Math.kt multiplication failure remains an explicit regression
in `../generated-power-tables-01/math-comparison.diff`: [u64::MAX,1] * 5^2048.
Math.kt is byte-identical to the baseline. Passing these tests is not a repair or
whole-library equivalence claim. Only 64-bit usize execution is verified here;
previous 32/64 limb-configuration evidence is unchanged.
